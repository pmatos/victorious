# Diarization runs the ungated community-1 pipeline, pinned, on CPU torch

Speakers are told apart by pyannote's `speaker-diarization-community-1` pipeline, which is why torch is now a dependency, as ADR 0001 foresaw. ADR 0001 called the diarization model gated; the original `pyannote/speaker-diarization-community-1` and its `segmentation-3.0` still are, which would leave CI and any machine without an accepted licence unable to run the real pipeline. We use the official `pyannote-community` mirror of community-1 (cc-by-4.0, not gated), pinned to one revision, fetched without a token and cached like the audio tagger of ADR 0003. If the mirror ever vanishes, `analyse` fails loudly and names `--no-speech`; the gated original can be used with `--diarization-model pyannote/speaker-diarization-community-1` and a token, or a local folder holding a pipeline. The startup check for a Hugging Face token stays although no model needs one now: story 38 asks for it and it keeps a gated model one flag away. Diarization runs once per Recording over the audio around Transcript segments only (padded, joined, with music silenced as Whisper saw it), so cluster identities are stable across Matches and cost far less than diarizing whole Matches. Enrolled voices are compared with the speakers' mean embedding from the same WeSpeaker embedder, by cosine distance, so the threshold does not depend on the pipeline's clustering space. Torch comes from the CPU wheels on Linux (a `pytorch-cpu` index in `pyproject.toml`), because there is no GPU path and the CUDA wheels add several GB.
