# The default Whisper model is large-v3-turbo

Speech is transcribed with `large-v3-turbo` (faster-whisper's name for `mobiuslabsgmbh/faster-whisper-large-v3-turbo`, int8 on CPU), not `small`, because the owner values accuracy over run time. We compared `small`, `medium`, `large-v3-turbo` and `large-v3` on five 300 s windows of one real Recording (25 minutes, 1615 reference words, 38.8% of the audio speech, with the product's own music masks, VAD, language choice and drop rules; diarization is model independent and was skipped), taking `large-v3` as the reference. Word error rate against it: `small` 28.0%, `medium` 22.7%, `large-v3-turbo` 17.2%; turbo and `large-v3` disagree by 17% with each other, which is the noise floor on game audio with overlapping voices and names. `small` missed 206 of the reference words (whole short sentences vanish) against 68 for turbo, and was unsure between English and Portuguese on 8 of 59 speech groups (so decoded twice) against 1. The price is speed: about 3 audio-seconds per second for turbo against 18 for `small` on this CPU, so the Whisper stage of a 3 h Recording (about 10,400 s inside Matches) takes about 45-60 min on a quiet machine and 1.5-2.5 h on a loaded one, instead of about 10 min and 15-25 min. This moves speech-on runs further from the 15-20 min target quoted in the README (issue #30 is not touched here); `--no-speech` is unchanged. `medium` is dominated (no faster than turbo, less accurate); `large-v3` is twice as slow again and stays reachable through the hidden `--whisper-model large-v3`, as does `small` for quick runs. A GPU path was checked and rejected: CTranslate2 has no ROCm backend and whisper.cpp with Vulkan is no faster.

Consequences. The first run downloads 1.6 GB (was about 480 MB) into the Hugging Face cache, and CI's cache key changed from `huggingface-whisper-small-...` to name the new model, because a static key that hits never saves the larger cache. The tests that load the real models now load turbo. Transcripts differ from those of earlier runs, but they are not part of the Observation cache, so a rerun always retranscribes and no cache version is bumped. As with `small`, the Whisper model is not pinned to a revision, unlike the audio tagger (ADR 0003) and the diarization mirror (ADR 0004); a vanished repository still fails with a `SpeechError` naming `--no-speech`.

Caveats. Five windows of one Recording, one group of speakers, English-dominant, no ground truth: the figures are agreement with `large-v3`, which favours turbo (same encoder, distilled from it), and turbo looked right where `large-v3` was wrong in places. Portuguese is untested because the sample has almost none, so the 8 of 59 vs 1 language result is about English speech being sometimes mistaken for Portuguese, not about Portuguese accuracy. Hallucinations on lobby and music audio are not fixed by a larger model: turbo and `large-v3` read lobby music as a Portuguese "Obrigado." at 0.6 confidence, which passes `is_speech` and the loop filter, so a false `pt` label is a known risk (`small` produced English "Thanks for watching." there). Timings come from one machine with 24 logical CPUs under a load average that swung between 7 and 65, so they are indicative. To revisit when labelled Portuguese audio exists.

Superseded in part by [ADR 0006](0006-sequential-whisper-decoding.md): the model stays `large-v3-turbo`, but it is decoded sequentially with the previous text as context, and the run-time figures above are about 1.4x longer.
